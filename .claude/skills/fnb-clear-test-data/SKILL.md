# 食材测试数据清理（临时）

此 skill 的依据是用户 2026-10-06 定义：全部食材相关数据都是测试数据；旧版食材、餐饮商品及销售订单、fnb_unit、食材上传记录与文件均可清除。员工个人信息和其他业务数据必须保留。该定义只适用于正式上线前。

## 生命周期

每次使用先查看本目录 `lifecycle.json`，并核对用户最新的上线说明及项目记录。`status=testing` 才允许预览、清理和文件重试；缺失、无效或 `retired` 一律停止。测试版本部署不等于正式上线。

用户明确食材系统正式上线时，或项目记录已标明正式上线时，先执行 `scripts/clear_test_data.py --retire`，将生命周期变更提交并推送到文档仓库 main，然后停止清理。退役不连接数据库或 S3；重复退役安全。不得将状态改回 testing，也不得通过复制脚本、修改检查或旧版副本继续使用。正式上线前应先处理完待重试文件清单。

## 执行

1. 阅读 [references/operations.md](references/operations.md)，确认目标库、范围及文件位置。源码及状态随 `snowmeet_ai_doc` 仓库同步；执行前同步 main，遇到生命周期冲突采用 retired 状态。不要使用离线旧副本。
2. 区分请求：创建/修改 skill、查看脚本、查看范围不授权实际清理。本轮创建 skill 没有执行生产清理。未来用户明确要求执行清理时，在执行前确认该请求仍覆盖目标数据库和文件；不因历史“所有 Python 自动执行”而推定数据删除已获授权。
3. 只通过明确的 `SNOWMEET_FNB_CLEAR_DSN` 连接目标；绝不读取 `SnowmeetApi/config.sqlServer`，不启动 API，不执行或 import `run_fnb_http_smoke.py`。先运行默认预览，向用户提供实际计数与文件数量；若范围符合当前已授权请求，继续 `--execute`，无需重复询问。仅要求查看时停在预览。
4. 使用脚本内精确白名单和关联选择。未知表、外部引用、共用个人文件、混合业务订单等导致拒绝时，报告具体阻碍；不得扩大范围或关闭约束。SQL 删除使用单个 Serializable 事务；文件只在已记录数据库提交后删除。文件失败保留清单，按用户已授权范围重试。
5. 汇报实际数据库结果、文件完成或待重试状态、保留范围及清单路径。没有实际执行就明确说明。凭据和清单不提交 Git。

脚本路径相对本 skill：`scripts/clear_test_data.py`。默认只预览，`--status` 查看状态，`--retire` 作废；没有重新启用选项。数据库入口、文件入口与文件重试均检查生命周期。验证方式和必要权限见参考文件。
