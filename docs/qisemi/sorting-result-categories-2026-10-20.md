# 库存排序与结果分类二次筛选

2026-10-20。用户要求库存页支持按名称、顶级分类的正序与倒序，并在搜索卡片下增加可横向滚动的结果顶级分类条，每项带括号数量。实现提交 `SnowmeetApi ai@d630e58e`。本轮开发与本机验证，未部署生产。

## 交互及口径

- “排序”提供名称、顶级分类两个字段，以及正序、倒序两个方向。服务端先排序再分页，同名用 ID 保持稳定顺序；分类排序缺档项始终最后。
- 分类条显示“全部（总款数）”及有匹配结果的“分类名称（款数）”。数量按搜索词、主分类、仓库和库存等主条件的全部结果统计，覆盖所有页；不是库存数量，也不是当前页条数。多个尺码归同款只计一次，同款跨顶级分类可分别计入。
- 点击分类后二次筛选，其他分类和其数量仍保留，可切换或点“全部”恢复；筛选及排序都回到第一页，分页保留筛选和排序，URL 可保存并恢复状态。
- 新的主搜索、仓库、顶级分类或库存条件清除旧二次选择；排序调整保留当前二次选择。没有完整可见分类的结果归入“未分类”，来源删除链仍受原遮罩控制。
- 分类条单行横向滚动，按钮有选中状态、键盘焦点与可访问名称，不拉宽整个页面。

## API

沿用 `GET Inventory`，新增 `resultCategoryId`（0 为未分类）、`sortBy=name|topCategory`、`sortDirection=asc|desc`。响应分页对象新增 `categoryFacets:[{id,name,count}]`、`unfilteredTotal`，详见 [接口契约](api-contract.md)。无 DDL、数据导入、鉴权或新路由变更。

分类统计复用已经过来源链与关键词筛选的 SKU 身份集合，不为每一分类另发查询。分类排序仅将短 ID/分类名映射传入当前页查询，库存仍只计算当前页款式。
