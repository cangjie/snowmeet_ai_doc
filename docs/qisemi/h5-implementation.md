# 七色米 H5 实现

2026-10-20。用户授权继续开发前端，沿用确认原型及小程序/食材管理 V4 的风格。代码已在 `SnowmeetApi/wwwroot/wecom/qisemi/`，四个文件为 `index.html,app.css,api.js,app.js`。`QisemiPageController` 将 `/wecom/qisemi` 及尾斜杠入口转到真实页面；**尚未部署**。

## 已实现

- 浅灰背景、白色圆角卡片、蓝色搜索与选中态；四个入口保持“查库存、业务单据、基础档案、更多数据”，默认查库存。
- 模块目录从 API 取得，对应原型 50 个入口；业务、档案、库存报表、历史版本、图片附件、工作表、原文件、快照核对都有真实接口来源，没有运行时演示数据。
- 商品关键词组合查询、仓库选择、款式分页；展开后保留全部尺码，按尺码与库存矩阵切换，查仓库、显示零仓、负库存标红、未知数量单列。
- 点击尺码进入带 SKU/仓条件的流水，再追溯来源单据；商品档案可以定位到同款并默认选中该 SKU。
- 单据按关键词、业务日期、红冲筛选，档案按来源启停/删除筛选；来源状态、草稿、历史版本和缺档占位有单独标记。
- 单据详情包含基本资料及商品明细、分账、核销、关联、流水、历史、文件和完整原始字段分区；列表/详情分区分页，返回列表保留原筛选和页码。
- 图片通过受控文件引用接口取得 Blob 预览；其他文件下载。请求头随文件请求一起发送；不把会话值放进 URL，不链接上游签名地址。款式缩略图可取同款任一尺码主图，缺图不影响库存。
- 平台工作表表头、原始行和原文件分开查看；来源核对问题及逐模块采集状态可浏览。空模块显示本次快照暂无记录，保留入口。
- 账套选择、库存/全业务分别显示采集时间；两类批次分别固定。批次变化提示显式刷新；网络失败可重试。切换页面终止旧请求，迟到的响应不覆盖当前页面。
- 搜索/筛选栏在请求前就显示；中文输入不会因为即时请求而丢字。保留大整数身份字符串，所有来源文字及原始 JSON 做 HTML 转义。

## 会话预留

不做登录或权限判断。API 客户端可以从 `sessionStorage` 的 `SessionKey` / `SessionType` 读取预留值，统一放到同名请求头；缺省也能访问。后续接入正式员工登录时，应统一替换会话提供器及服务端过滤器，不为某一图片接口另造登录口径。

## 本机验证

```powershell
node --test SnowmeetApi.Tests/H5/qisemi.test.cjs
node SnowmeetApi.Tests/H5/qisemi.browser.cjs
```

浏览器脚本依赖 Playwright 和本机 Chrome，可用 `QISEMI_H5_BROWSER` 指定浏览器路径。使用本机静态服务及明确的合成 API，不启动生产 Startup，不读生产配置。截图默认进入 workspace `.local/qisemi-h5-qa`，不进入 Git。

- 客户端 4 项测试验证会话头、批次固定、文件响应及 HTML 转义。
- 浏览器逐个访问 50 个入口，验证尺码/矩阵/零/负/未知数量、流水追单、原图预览、红冲查询、空结果、409 刷新与迟到响应；检查 320/390/768/1280 宽度，矩阵单独在 320/390 宽度验证可横向滚动。
- 完整抓取快照在本机隔离 LocalDB 复制库联调，真实 Fischer 同款返回 25.5、26.5、27.5；原图预览使用本机保存的原文件字节，未把生产 IAM 凭据放进本机预览。

本轮没有改线上 nginx、域名、企业微信应用入口或生产服务；没有在真实企业微信手机内验收。生产 S3 实例角色读取、企业微信域名和手机缓存须在后续获准部署时核实。日常抓取/增量导入仍不在当前实现范围内。
