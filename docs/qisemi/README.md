## 数据库设计审阅

[表结构设计稿](database-design.md) 包含 37 张 `dbo.qsm_*` 表的字段、类型、关联、索引和导入规则；[来源映射](database-source-map.json) 覆盖 61 份业务 JSONL、20 份原表工作表、媒体与快照核对资料。

- 所有表统一 `valid bit DEFAULT 1`：1 有效，0 逻辑删除，并保存删除时间、操作者、原因和审计。停用、红冲、来源删除、历史版本分别保存。
- 款式、尺码 SKU、归组关系和各仓库存分开；关键词命中尺码后仍展示同款全部尺码，保留零与负库存。
- 结构化查询字段与完整原始记录同时保留；单据、历史版本、报表和原表不重复累计。
- 批次核对成功后再发布，库存与全业务可分别更新并显示各自时间；未来零售通过映射关联，不直接覆盖现有库存或支付。

表结构已获确认，迁移工具见 [sql_import](../../tools/qisemiyun/sql_import/README.md)。已将 2026-10-18 完整抓取快照迁入 `snowmeet_new`：225,911 条原始记录（含元数据）、5,808 个 SKU、12,177 个单据身份；各仓数量与总表一致。图片附件与原表进入 S3 私有区，128 项来源数据核对问题单独保留。日常新快照同步尚未实现。

## 界面原型

用户认可已有库存查询，并要求以此为最重要功能，让抓取到的七色米业务内容都能展示。当前扩展为四个入口，默认进入库存查询；继续沿用小程序与食材管理 V4 的浅灰背景、白色圆角卡片、蓝色主色、员工入口样式。

| 入口 | 内容 |
| --- | --- |
| 查库存 | 同款归组、尺码、各仓数量与库存对照，按尺码跳到库存流水 |
| 业务单据 | 采购、销售、预订单、退货、草稿、调拨、盘点、借入借出、出入库、收付款、核销、转账、收支和客户资产 |
| 基础档案 | 商品配件、分类、计量单位、仓库仓位、门店、客户供应商、结算账户、收支项目、员工与角色 |
| 更多数据 | 库存总表、各仓明细、库存流水、销售商品明细、历史版本、结存、图片附件、平台原表和数据快照核对 |

源码分为 [库存交互](prototype/inventory.html)、[业务浏览](prototype/data-browser.html) 和 [模块映射](prototype/modules.json)。检查映射覆盖抓取结果的 61 份业务 JSONL、20 份平台原表工作表、图片附件索引及快照核对信息，见 [完整覆盖清单](data-coverage.md)。界面合并重复档案口径，把补充明细放进所属单据，共 50 个模块入口；不会把历史版本和当前单据重复累计。

在当前目录生成可独立打开的原型：

```text
python prototype/build.py
```

结果是 `prototype/out/index.html`，生成目录不进 Git。可加 `--output <本机输出文件>` 指定位置，或 `--image <本机图片>` 加入可选的演示商品图；图片不经网络下载、不写入源码。对话预览由同一份源码生成。

业务交互已用临时 DOM 环境检查：保留原库存检查，并遍历 50 个模块入口、33 个非空记录详情，验证补充明细、日期状态筛选、原表、图片预览、历史版本，以及“库存 → 流水 → 来源单据”和“档案 → 库存”。这些是 DOM 与语法检查，未进行企业微信手机实测或线上发布。

所有数量、示例商品编号和部分产品组合均为合成数据，不得作为实际库存使用。Fischer U06424 的字段组织参考已有商品档案，不在原型中放真实业务 ID、采购成本、账号或登录信息。

- 按商品名称、品牌、型号、款号、示例商品编号、尺码模糊匹配，多个关键词组合搜索。
- 搜索结果按款式显示。卡片展示款号、雪季、颜色、尺码数和所选仓库的账面合计。
- 展开商品后，默认按尺码查看；切换尺码，列出各仓数量；“库存对照”同时比较该款各尺码和仓库。
- 按某个尺码或编号命中时仍展示同款全部尺码，保留零库存尺码。
- 提供仓库选择、展开后的仓库关键词筛选、零库存仓显示开关；默认收起零库存仓。
- 负库存保留原符号并标红、标注“负库存”；合计包含负数，不把账面合计标作可售库存。
- 页面显示快照时间，并说明正式数据以最近一次成功导入为准。
- 搜索无结果、尺码全为零、仓库关键词无匹配都有单独提示。
- 业务列表默认显示全部日期、全部状态，支持业务日期和状态筛选；红冲、停用、草稿与历史版本有明确标记。
- 单据可查看基本信息、商品明细、核销、分账、盘点差异、借用归还、关联资料、图片附件和完整采集字段。
- 图片附件可按商品、单号或文件名及类型筛选，再查看原文件和关联来源。
- 平台原表提供总表与商品明细的字段核对；商品、客户等单表不伪造商品明细页；收付款补充表分开展示收、付款记录。
- 空模块保留入口，明确显示示例快照暂无记录；历史版本、原表和其他载体不重复累计业务记录。

## 已确认的界面规则

1. 采用“款式卡片 → 尺码 → 各仓数量”，同时提供“库存对照”视图。
2. 默认隐藏零库存仓，但保留所有尺码；问题仓、核对仓、负库存仓都允许查询，当前显示的是账面库存。
3. 同款归组结合品牌、款号、完整型号、雪季、颜色和性别，尺码作为子项；不只删除名称尾部的数字。同款不同雪季、颜色、硬度不能误合并。字段缺失或冲突时先单列，具体持久化归组规则见第二阶段审阅稿。
4. 采用四个入口和上述全部业务浏览范围；单据补充详情归入所属单据，图片附件和平台原表另有集中入口。

以上界面方案和表结构均已确认；数据库执行状态见本文开头，未来零售映射表本次保持为空，不写入既有零售库存或支付。

## 可体验场景

1. 搜索 `Fischer 110`：看到不同雪季分开的两款。
2. 搜索 `U06424 26.5`：命中指定款式与尺码，展开后仍保留 25.5、26.5、27.5。
3. 切换 27.5：显示暂无库存；打开“显示零库存仓”可看所有示例仓库。
4. 切到“库存对照”：各仓为行、尺码为列，保留零与负值。
5. 搜索 `不存在的雪鞋`：显示空结果；清空后恢复全部款式。
6. 业务单据 → 销售单 → 详情 → 关联资料：看销售分账、库存流水、历史版本和原表。
7. 业务单据 → 盘点单 → 商品明细：看账面、实盘、差异；收款单可看核销，借入借出可看归还。
8. 基础档案 → 商品档案 → 查询库存：回到原有同款、尺码库存界面。
9. 更多数据 → 图片与附件：按关键词或文件类型筛选并预览；平台原表可查看总表及商品明细。
10. 打开其他入库、结存记录等空模块：明确显示暂无记录，模块入口保留。
