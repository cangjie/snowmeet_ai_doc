## 界面原型

源码：[prototype/inventory.html](prototype/inventory.html)。采用小程序与食材管理 V4 的浅灰背景、白色圆角卡片、蓝色主色、员工入口样式；输入框使用 16px 字号。

源码是可直接在对话中体验的自包含片段。业务交互已用临时 DOM 环境检查，覆盖搜索归组、命中尺码后保留全部尺码、零与负库存、仓库筛选与对照、空结果和交互状态保存；未进行企业微信手机实测或线上发布。

所有数量、示例商品编号和部分产品组合均为合成数据，不得作为实际库存使用。Fischer U06424 的字段组织参考已有商品档案，不在原型中放真实业务 ID、采购成本、账号或登录信息。

- 按商品名称、品牌、型号、款号、示例商品编号、尺码模糊匹配，多个关键词组合搜索。
- 搜索结果按款式显示。卡片展示款号、雪季、颜色、尺码数和所选仓库的账面合计。
- 展开商品后，默认按尺码查看；切换尺码，列出各仓数量；“库存对照”同时比较该款各尺码和仓库。
- 按某个尺码或编号命中时仍展示同款全部尺码，保留零库存尺码。
- 提供仓库选择、展开后的仓库关键词筛选、零库存仓显示开关；默认收起零库存仓。
- 负库存保留原符号并标红、标注“负库存”；合计包含负数，不把账面合计标作可售库存。
- 页面显示快照时间，并说明正式数据以最近一次成功导入为准。
- 搜索无结果、尺码全为零、仓库关键词无匹配都有单独提示。

## 待用户确认的界面规则

1. 是否采用“款式卡片 → 尺码 → 各仓数量”，同时提供“库存对照”视图。
2. 默认隐藏零库存仓，但保留所有尺码；问题仓、核对仓、负库存仓都允许查询，当前显示的是账面库存。
3. 同款归组建议结合品牌、款号、完整型号、雪季、颜色和性别，尺码作为子项；不只删除名称尾部的数字。同款不同雪季、颜色、硬度不能误合并。字段缺失或冲突时先单列，后续规则待确认。

以上是界面与业务口径提案，尚未确定数据库实体、表名、字段、索引或零售对接接口。确认原型后，第二阶段再设计 SQL Server 结构与未来零售映射。

## 可体验场景

1. 搜索 `Fischer 110`：看到不同雪季分开的两款。
2. 搜索 `U06424 26.5`：命中指定款式与尺码，展开后仍保留 25.5、26.5、27.5。
3. 切换 27.5：显示暂无库存；打开“显示零库存仓”可看所有示例仓库。
4. 切到“库存对照”：各仓为行、尺码为列，保留零与负值。
5. 搜索 `不存在的雪鞋`：显示空结果；清空后恢复全部款式。
