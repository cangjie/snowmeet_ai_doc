# 列表自动图片与默认名称升序

2026-10-20 晚更新：本页增强现已获确认并部署为 `ai@af2b9e4c`；见 [生产验收与中断记录](deployment-query-enhancements-2026-10-20.md)。下方保留开发时的验证边界。

2026-10-20。用户要求排序默认按名称升序，并指出商品图片只有点击展开后才显示。实现提交 `SnowmeetApi ai@f6a5195a`。本轮只修改 H5，不部署。

- 原因：此前只在 `expand()` 读取款式详情成功后调用 `loadThumbnail()`，初始列表没有触发图片请求。
- 修正：当前页列表返回后即自动加载缩略图，每页两个并发任务，库存列表不等待图片；沿用带预留会话头的私有文件接口，不依赖展开或详情接口。图片到达只更新该款图片节点，不重绘输入框或筛选条。浏览器对折外图片延后解码。
- 新查询、离开页面时取消旧请求；序号检查阻止旧图片写入新页面。当前页图片复用已有 Blob URL，离开当前款集合或清理缓存时释放。没有图片、读取失败、解码失败有占位，库存不受影响。
- 不带排序参数进入、重新搜索或清空搜索时使用名称升序；手动更改后继续保留筛选和分页，显式带降序参数的旧链接仍按其参数显示。当前本机页面已切换为名称升序。

JavaScript 语法和客户端 4/4 通过。真实本机页面未点击任何商品时，当前 `XTR RC4 85 HV` 两款均折叠、两张图片已解码（naturalWidth=587）。从分类降序重新搜索恢复 `sortBy=name&sortDirection=asc`，23.5 在 24.5 前。浏览器错误为空，截图与 DOM 证据保存于 workspace `.local/qisemi-auto-photos-20261020/`。后端无改动，本轮未重跑 .NET/162 模块/50 入口/四宽度全套或企微真机；数据仍是既有快照。
