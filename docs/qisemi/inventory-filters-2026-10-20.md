# 七色米库存筛选增强

2026-10-20。用户要求库存页默认只看有库存，并增加仓库、顶级商品分类筛选。功能提交 `347209a1`，经生产预检优化后以 `SnowmeetApi ai@99a6e306` 部署；见 [本轮部署记录](deployment-filters-2026-10-20.md)。

## 页面行为

- “顶级分类”默认“全部分类”，只列来源系统真正的顶层商品分类。选择后包含该节点及所有有效下级品牌、雪季等分类，不按名称猜分组。
- “筛选仓库”默认“全部仓库”。选择后列表数量、尺码数量和展开的各仓明细都使用所选仓库；浏览器前进后退时也会清除旧仓明细缓存。
- “只看有库存”默认勾选。任一同款尺码在查询范围内有正库存即保留；全部仓库使用来源 SKU 总库存，指定仓库使用该仓账面库存。负数、零和未知均不独立满足条件。取消勾选可查看全部款式。
- 关键词、顶级分类、仓库和库存条件一起决定结果，再计算总数与分页。搜索、清空关键词和翻页保留筛选；修改分类、仓库或库存条件回到第一页。
- 关键词命中某个零库存尺码时，只要同款其他尺码有正库存，仍可找到该款。展开始终保留同款所有尺码。
- 静态资源版本为 `20261020-stock-filter`，避免复用旧的企微页面脚本。

## 接口

新增只读 `GET /api/Qisemi/TopCategories`，归入库存批次，保留 SessionKey/SessionType 请求头和既有无鉴权策略。七色米 GET 操作现为 28 个。

`Inventory` 新增 `topCategoryId` 与 `inStockOnly`。旧 `categoryId` 仍精确筛选款式分类；库存筛选参数 API 缺省 false，前端缺省主动发送 true。参数类型、范围、批次变化与逻辑删除规则沿用原有契约。

顶级分类从有效商品分类中取得，且检查分类原始记录、模块和发布批次。选择分类后遍历有效后代，用 SKU 的实际分类参与款式查询。原始来源记录或中间分类被逻辑删除时不会继续沿已删除节点取下级商品。

库存 SQL 先确定符合条件的款式再计数分页，仅对当前页计算尺码合计。真实快照测试发现内存紧张时原库存哈希查询等待 `RESOURCE_SEMAPHORE`；两处款式匹配查询限制内存授予与并行度，避免为小查询预留过大内存。未修改服务器内存配置、表结构、业务数据或发布指针。处理依据：[Microsoft SQL Server 内存授予排查](https://learn.microsoft.com/en-us/troubleshoot/sql/database-engine/performance/troubleshoot-memory-grant-issues)。
