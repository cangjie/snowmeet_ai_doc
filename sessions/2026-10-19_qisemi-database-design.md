# 七色米 SQL Server 设计：第二阶段待确认

用户认可库存主入口及全业务浏览原型，指示“下一步设计数据库，每个表都需要有删除标志，来进行逻辑删除”。这完成第一阶段确认，允许第二阶段设计；第三阶段仍必须先取得表结构确认。

交付 [37 张表结构审阅稿](../docs/qisemi/database-design.md) 及 [来源映射](../docs/qisemi/database-source-map.json)。每张表包含 `valid bit DEFAULT 1`、删除时间/操作者/原因、审计时间及并发版本；停用、来源删除、红冲、历史版本和本地逻辑删除分别保存。

设计保持款式/SKU/仓库库存分离，支持同款多尺码与关键词查询；采集批次和完整原始记录保留全部字段。单据稳定身份、采集版本、商品行、归还关系、账户分账和核销分别建模；媒体内容与业务引用分离，原表按工作表与原始行保留。预留本站商品、门店仓库及零售明细映射，不修改现有零售表。

只读核对本机导出和现有 `Product`、`Retail`、`Shop`、Fnb v4 逻辑删除映射。发现来源主款 ID 缺失、销售单号重复、流水缺少可靠唯一 ID 且有重复来源行，故不能按单号或内容哈希直接去重。销售商品报表同时包含销售和销售退货，按 `BusiType + SaleId` 关联对应业务类型，不能把全部 `SaleId` 当成销售单。来源 ID、载体行号、版本和匹配歧义分别保留。各仓省略零账面行，只能在逐仓成功范围补账面零，不能把失败漏采当零。

来源映射核对全部 61 份业务 JSONL、20 份平台原表工作表以及媒体索引。数量和字段结构审计脚本、原始数据及检查输出仅在本机 `.local/qisemi-db-design/`，不提交业务记录、实际业务 ID、图片或凭据。

文档检查通过：37 个表定义编号连续且全部继承逻辑删除字段，来源映射与实际文件集合一致，映射引用的查询表全部存在，设计稿和 README 的本地链接有效；`git diff --check` 无空白错误。这些仅为设计文档检查，不是可执行 SQL 或导入程序测试。

第二阶段仅为设计与文档一致性检查；没有连接生产数据库，没有执行建表/导入，没有实现后端或发布 H5。空模块的专有字段映射保留待实样验证，设计不声称已验证真实导入性能、SQL DDL 或手机体验。用户确认本稿后才进入第三阶段。
