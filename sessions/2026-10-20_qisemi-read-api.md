# 七色米后端只读接口开发

用户范围：按已确认的七色米原型在 SnowmeetApi 开发 API；请求头预留 `SessionKey` 和 `SessionType`，本期暂不鉴权；完成后等待确认，不部署。用户要求额度不足时恢复后继续；曾误设每日续办，用户指出后已停用，不保留每日执行需求。

## 实现

- `/api/Qisemi` 下 27 个 GET 操作，覆盖同款库存、SKU/档案、当前与历史单据、商品/分账/核销/关联/流水/文件/原始字段分区、销售商品报表、图片附件、平台原表、快照与核对。
- 使用迁入的 37 张 `qsm_*` 表与现有 SQL Server 配置，不增加表、不导入新批次、不写既有业务数据。
- 请求级会话头读取集中在 `QisemiSessionFilter` / `QisemiSessionContext`，Swagger 自动列出两个可选请求头。
- 库存使用已保存的款式关系，按某尺码命中仍展开全部尺码；完整仓缺行推定零、未完整/已删除的原行返回未知，保留负数。库存和业务分别使用当前发布批次；分页携带 batchId，变化返回 409。
- 每次查询核对源、批次、模块、原始记录和父对象的有效链路；SQL 参数化。大整数返回字符串，业务时间带 +08:00、UTC 审计和采集时间带 Z。
- 50 入口模块目录从已批准原型和来源映射生成，作为程序集资源随部署发布；不含演示业务数据。空模块保留入口，完整原始 JSON 和补充数组可浏览，私人凭据与存储键不对客户端输出。
- 文件按引用身份校验后由服务端流式读取既有私有 S3，不公开对象；处理来源文件名仅 `main` 的情况，使用已保存的图片 MIME。HTML/SVG 等不内联。
- [API 契约](../docs/qisemi/api-contract.md) 说明路由、参数、响应、各入口映射和验证方法。

## 验证

完整 225,911 条原始记录在隔离 LocalDB 恢复，原始哈希和库存核对通过。SQL Server 用例验证分组、尺码、零/负/未知库存、年份筛选、红冲、历史版本、原表、软删链路、跨源与批次固定，以及文件父对象删除后无法读取。

原始记录分页与库存默认 30 款首页在完整快照上暴露了执行计划问题，已修复：原始删除遮罩先按请求物化；库存平面匹配并分页后才计算当前页数量。稀疏原始键匹配显式使用哈希连接，包含相关子查询的数量计算不强加该限制。完整快照用例遍历 162 个模块逐项核对记录数，并单独验证 30 款首页与真实雪鞋/单据关联。

最终常规 .NET 回归 **506 通过、26 跳过、0 失败**；跳过的为原有专用食材数据库测试。另单独运行完整快照 **3 项全部通过**：162 模块计数逐项一致、真实雪鞋与单据关联、默认 30 款首页（本机测得约 0.6 秒）。

H5 **4 项客户端测试通过**；浏览器遍历 **50 个模块入口**、320/390/768/1280 宽度、矩阵窄屏、零/负/未知库存、附件、红冲、空结果、批次刷新及旧响应竞争，无浏览器异常。真实本机 API + LocalDB 页面中，Fischer 同款 25.5/26.5/27.5 与本地原文件图片预览均已验证。

本机验收日志及截图位于 workspace `.local/`，没有进入 Git。此前中止运行留下的 2 个合成测试库已在确认 LocalDB 与命名范围后清理；完整快照复制库暂保留供本机预览。预览工具、临时数据库配置和真实截图不进入 Git。

## 交付边界

- 不部署、不启动生产应用、不修改生产配置或生产数据。
- 用户已在同一会话授权继续前端，H5 已接真实 API，本机真实快照联调通过；没有企业微信手机验收。见 [H5 实现](../docs/qisemi/h5-implementation.md)。

- S3 流读取用 SDK 桩验证，不把本机持有生产 IAM 凭据作为测试条件；上线时仍需在实例角色环境验收真实图片。
- 本机临时预览只监听 `127.0.0.1:5591`，使用隔离复制库和本机原图，不读取生产连接文件、不启动采集告警服务；它是本机审阅辅助，不作为生产发布脚本。
