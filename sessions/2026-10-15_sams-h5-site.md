# 2026-10-15 山姆商品查询 H5：从设计到上线 https://mini.snowmeet.top/sams/

按时间线整理。接续同日京东补价收尾（见 [2026-10-13_jd-price-resume-laptop.md](2026-10-13_jd-price-resume-laptop.md)）之后，用户要用抓到的山姆 App 商品做一组手机网页。改动在 `sams_scrape` 仓库（分支 `sams-h5`）和 mini 服务器 nginx；SnowmeetApi、数据库都没动。笔记本（Intel，macOS 13）上完成。

## 1. 需求与设计（brainstorming）

### 1.1 用户原话与决定

- 原话：「根据抓取到的山姆会员店的商品，做一组 web 页面，从 https://mini.snowmeet.top/sams/ 下访问。H5 页面适配手机即可。……最好是放在另外的地方（不放 SQL Server）。」
- 逐项确认：
  - 用途：店员查商品和价格；
  - 访问：不加登录；
  - 图片：京东图 + 截图裁小图（选项 B），「图片放在 S3 存储桶里」；
  - 架构：网页、数据、图片都放 S3 `upload/sams/`，mini nginx 把 `/sams/` 转给 `img.snowmeet.top`；
  - 价格：「价格就以山姆 app 为准即可，抓京东价格只是为了确认两边一样」→ 不放京东价格，只在京东有的 17 个不放；
  - 页面：「网页需要按照分类显示，并且可以搜索。以后更新 jsonl 和 s3 就可以了。」
- 设计文档：`sams_scrape/docs/superpowers/specs/2026-10-15-sams-h5-design.md`。

### 1.2 设计里后来补的几处

- nginx 的 `proxy_pass` 用变量 + `resolver`：直接写域名只在启动时解析一次，CloudFront 换 IP 后就转发不到。
- 用 `location ^~ /sams/`：防止 server 块里按扩展名匹配的正则规则截走图片请求。
- 脚本名 `site.py` → `sams_site.py`：原名和 Python 自带的 `site` 模块重名。
- 识别缓存按截图内容的 sha1 判断是否有效：重新抓取后同名截图内容变了会重新识别。

## 学到的小知识

1. **同一识别程序、同一识别版本，在不同 macOS 上结果不同**：行高、横坐标、分行、颜色都会变。按一台机器调的阈值换机器就丢数据；按「内容」（标题开头、价格）匹配比按「位置阈值」稳。
2. **试验先用临时脚本量化，再走测试先行落地**：825 → 805 的数字和 80 张抽查，是改规则的依据。
3. **SnowmeetApi 不处理 HEAD 请求**：`curl -I` 查 Swagger 得 404 是误报，验收用 GET。
4. **nginx 锚点要唯一**：同一配置文件里有多个站点时，`location / {` 往往不唯一；插入脚本强制「正好出现 1 次」才改，避免插错站点。
5. **经美国服务器转发往 mini 传小文件很慢**（约 28 KB/s），几千个小文件的全量传输要二三十分钟。
6. **截图早于图片加载会看到空白**：先用脚本确认 `img.complete` 和 `naturalWidth`，再下结论。
7. **「共用同一张图」是发现错图的好办法**：随机抽查看不出同系列商品配错，按内容指纹找重复一次就查出来了。
8. **发布中断不用怕**：S3 只在 rsync 全部传完后才开始上传，`index.html` 最后才传，中断时线上不受影响；rsync 重跑会接着传。
