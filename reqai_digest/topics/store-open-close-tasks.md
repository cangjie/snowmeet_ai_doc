## reqai 提案要点（未确认，不是决策）
- 用「门店营业班次」建模（暂名 `shop_shift`，状态 open / closing / closed），不要只在门店表加 `is_open`。同一门店同时只能有一个未关闭班次；`business_date` 只用于展示和统计。
- 任务模板按阶段分：开门 / 营业中 / 关门。任务类型包括确认、数量盘点、金额盘点、文本、拍照、清单。开门时把模板复制成本班次的任务快照，之后改模板不影响已开的班次。
- 任务状态沿用养护任务的「未开始 / 已开始 / 已完成 / 强行中止」，另加「已豁免」。强行中止不算完成。豁免时记录豁免人、时间和原因。
- 关门预检和最终关门用同一套服务端校验，返回结构化的阻断项（如 `OPENING_TASK_PENDING`、`RENEWAL_ORDER_PENDING`）。提交时在事务里再校验一次。
- 豁免只针对任务，不能用来豁免「未确认续租订单」。
- 不复用 `care_task` 表（它绑定具体养护单，有发板、热蜡、安检等副作用），只借鉴它的交互和状态机。
- 开关门权限按「有效员工身份」判断，不写死 `title_level >= 100`。
